输出与验收

共用报告内容

按用户选定格式交付同一套有证据支持的结论，避免不同格式丢失待核实状态。报告目录严格按 report-structure.md，使用思敏老师材料的六大部分及下级栏目；不采用另一套市场、技术、模型等平行章节。产品专属名称与场景可替换，层级和栏目顺序保持一致。

每个分析步骤下分别列“已经明确确认”和“待确认核实”。缺证据或不适用的栏目写明边界及下一步验证，不留空或填造。评分、Agent 和提示词等栏目保留，不意味着必须产出分数、虚拟角色或系统提示词原文。

二次验证结果、剩余问题、证据目录和关键截图收在“（六）架构总结”末尾，用普通标签或表格呈现；如需独立验证清单可另交配套文件，不改变正文六部分目录。报告长度随任务深度和材料而定。

图表与评测

默认包含用户旅程、人机分工、模型与费用清单、架构总览；可在正文中使用紧凑表格或图，避免无信息重复。复杂 Agent 产品按需增加协作流程与上下文图。架构节点尽量使用名词，箭头说明调用或信息流，待核实节点明确标记并引用证据。

可按端到端结果、交互共创、执行协作、基础能力建立评分维度，但不得将动画案例的指标和权重照搬到所有产品。定量评分先确定指标、可观察标准、权重及总分；无法评估的标为未评估，不填零或虚构分数。不完整评分不用于全产品评级。一次成功不能证明稳定成功率。

Markdown 文档

交付 UTF-8 .md 与引用媒体目录。使用相对媒体路径便于整体搬迁，最终回复给出绝对文件链接。架构图可用 Mermaid 或兼容的静态图；附文字说明，避免接收端不能渲染时丢失核心结论。保留视频链接、时间点和证据编号。

HTML 报告

生成本地可打开的 .html，配套资源使用相对路径或内嵌；不因选择 HTML 自动部署网站。未定风格时只提供基础的清晰排版、目录、适配屏幕与打印样式，颜色之外也用文字区分确认状态。

架构图与截图应能在本地打开时显示；优先内嵌 SVG 或随文件交付静态图，不依赖未检查的远程脚本。对引入的材料文字进行 HTML 转义，不直接执行材料内脚本。打开最终报告检查内容、导航、图表、媒体路径及窄屏可读性。用户后续制定视觉风格时再更新呈现，不改变分析标准。

飞书文档

先检查当前环境是否有实际可用、具备相应权限的飞书文档创建/写入能力，并确认用户提供的目标文档或创建位置；只请求完成任务必需的信息。不得编造连接器或称本地文档为已写入飞书。

有写入能力和明确目标时，按用户选择生成或更新文档，检查标题、表格、截图、来源链接和架构图在飞书中的结果。更新现有文档只修改授权范围。接收端不支持 Mermaid 时改用可显示的静态图。

没有写入能力或目标访问受限时，明确说明限制，先交付可导入飞书的 Markdown 与配套图片，并说明原生飞书文档尚未创建；不以复制链接或本地导出文件冒充完成。后续用户提供可用目标和权限后再写入。

交付检查

  • 六大部分、下级栏目和顺序符合 report-structure.md；产品名称与测试场景已替换，无遗留示例结论。
  • 端别、版本、资料日期、实操与公开资料范围写清楚。
  • 分析围绕同一任务贯通各层，交付结果有可访问证据。
  • 每步两种状态齐全，关键待核实项已经尝试二次验证或注明所需材料。
  • 架构图、摘要、正文和验证清单的确认状态一致。
  • 价格、积分消耗和内部成本分开；单位、权重与合计一致。
  • 截图、视频、引用与成品链接可定位；没有泄露无关敏感信息。
  • 飞书明确写入与否；Markdown 检查媒体路径；HTML 实际打开验证。
