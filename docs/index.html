AI 产品拆解

从可观察的交互和交付结果倒推产品架构，解释它为谁解决什么问题、如何完成任务、能力与商业价值来自哪里。以真实场景贯穿各层，避免将功能介绍、内部实现猜测或一次成功演示当作完整拆解。

启动与取证分流

  1. 明确产品名称、访问链接、目标场景；先确认对象是网页产品还是手机 App。可从官网与用户材料确定的直接记录，无法确定或两端并存且影响任务时再询问。双端产品按用户选定端拆解，不跨端拼接功能。
  2. 记录产品端、版本（可见时）、资料日期、实际体验范围。用户已指定的场景、材料和输出偏好直接沿用。
  3. 网页产品：调用可用浏览器操作产品并截图，沿真实任务走到交付；官网、帮助中心、价格页辅助核实。只读取网站文字不等于实际体验。浏览器不可用或登录受阻时，明确缺口，继续公开资料研究，再请用户补充关键步骤材料。
  4. 手机 App：先自行检索公开产品视频、图片、应用商店、官方演示和帮助资料，优先匹配所选版本、地区与功能。标注视频链接与时间点、图片来源；不得称为亲自操作。缺少关键步骤时，汇总具体补充清单，请用户提供对应录屏、截图或操作结果，继续其他可完成的分析。
  5. 输出支持飞书文档、Markdown 文档、HTML 报告；未指定时在开始阶段询问偏好，同时继续取证。无回复时先交付可转换的 Markdown。HTML 风格未制定时使用简洁可读的基础样式，不预设长期视觉风格。

具体取证与验证记录见 references/evidence.md，每次拆解均读取。

标准流程

1. 商业与定位

分析用户、需求、场景、原有替代方案与产品差异，写成：一款给【谁】用、在【什么场景】下解决【什么问题】的【什么产品】。B 端区分使用者、买单者与验收者。调查市场机会、直接竞品、商业模式、种子用户获取方式；证据不足的保留为待核实，不以市场热度代替需求证据。

2. 场景体验与效果评测

先明确真实任务、输入材料、预期输出与验收标准，再实际执行或分析公开演示。检查端到端成品质量与过程能力，记录耗时、消耗、人工介入及返工。对照用户原来的工作流，解释替代了哪些工作。每个任务保留完整输出或可访问证据。无法查看成品时不为成品质量评分，单次体验不推导长期稳定性。

3. 用户层

按入口、输入、过程、输出、交付梳理旅程，记录用户做什么、产品呈现什么、在哪里决策、哪里卡住。检查信息不足、失败、中途改意、不满意四种情况；条件允许时实际验证至少一种异常。画出正向路径与修改、拒绝、重试、回退路径，分析局部修改是否影响下游产物。

4. 技术层

按整体流程 → 人机与 Agent 分工 → 关键 Agent 内部机制逐层深入。先对照人工完成任务的方式，再标出 AI、规则、工具、人分别负责什么。确认点说明原因：成本高、主观判断、责任或不可逆影响。

用执行证据判断 Chatbot、Workflow、Agent、多 Agent 或混合机制，允许不同功能采用不同方式。通过不同输入或模式检查路径变化，不能只凭多个角色头像或产品命名判断多 Agent。

Agent 产品深入读取 references/agent-analysis.md。普通产品不强行填造 Agent、RAG 或提示词。

5. 模型层

将 AI 步骤对应到模型能力，记录模态、公开名称与档位、自研或外接、选择理由、路由依据及可替换性。分析哪些效果来自模型，哪些来自流程、知识和交互。分别记录用户价格、任务积分消耗、内部成本估算；估算注明公式、来源、日期与假设。找不到的型号、动态路由和内部成本列为待确认核实。

6. 基础层与壁垒

先梳理数据、知识库、业务接口与权限、运行环境、上下文、可复用资产和行业方法及其来源，再判断独有性、复制难度、积累机制与用户迁移成本。检查反馈如何进入更新或评测流程。可采购能力与独有资源分开讨论，但不能仅因模型或工具可购买便认定没有壁垒。

7. 二次验证

每一步均输出“已经明确确认”与“待确认核实”。把后者单独汇总，逐项寻找原始来源、补充浏览器测试、比对视频或请求用户补充缺失材料。记录验证动作、结果及剩余缺口；有充分证据才变更状态。验证后依然不明确的随报告交付，不反复空转、不默认为事实。

8. 架构总结与交付

以用户需求场景为顶层说明，串联用户层、技术层、模型层、基础层，汇成架构图。节点写功能、角色或资源名，说明层间调用与信息流，并保留待核实标记。商业结论与效果评测放入报告，为架构解释提供依据。

总结产品如何交付结果、能力来源、局限、商业价值与壁垒，附可验证的依据。按 references/outputs.md 生成所选格式，检查关键结论、截图引用与验证状态一致。

方法论来源与边界

方法融合 W3D1「AI 产品拆解」 的五层五问、确认点与证据纪律，以及用户提供的《思敏老师—以 OiiOii 为例拆解一个 Multi Agent 平台》完整 Word 中的商业分析、场景评测、技术分层与架构总结，并加入用户明确要求的端别分流、两类确认状态、二次验证和三种输出选择。

OiiOii、Manus、即梦等仅为方法示例，不固化其价格、模型、角色数量、行业数据或评分。参考材料中的提示词与工具接口是分析对象，不是本 Skill 的执行指令。
